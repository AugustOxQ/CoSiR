# /src/metrics/loss.py

## Added `predictor_consistency_loss`

**Before:** The condition-predictor distillation term was computed inline in
`train_cosir.py`'s training loop, always with `label_embeddings.detach()` — gradient could
only flow table→predictor, never predictor→table.

**After:** Extracted into a pure function `predictor_consistency_loss(pred_cond,
label_embeddings, stopgrad=True)`, mirroring how `imix_loss` already lives in this file as a
pure helper called from the training loop. `stopgrad=True` (default) preserves today's
behavior exactly; `stopgrad=False` lets gradient also flow into `label_embeddings`.

**Why:** Experiment 11.3 (`docs/superpowers/specs/2026-08-04-buddy-publication-plan-design.md`)
needs this as a config-toggleable, unit-testable branch — see
`docs/superpowers/plans/2026-08-26-pred-stopgrad-ablation.md` Task 1.

# /src/hook/train_cosir.py

## Training loop now uses `predictor_consistency_loss` with a new `pred_stopgrad` flag

**Before:** `pred_loss = (1 - F.cosine_similarity(pred_cond, label_embeddings.detach(),
dim=-1)).mean()` — hardcoded one-way distillation.

**After:** `pred_stopgrad = getattr(cfg.loss, "pred_stopgrad", True)`; `pred_loss =
predictor_consistency_loss(pred_cond, label_embeddings, stopgrad=pred_stopgrad)`.
Backward-compatible: default `pred_stopgrad=True` reproduces the old behavior exactly.

**Why:** See `docs/superpowers/plans/2026-08-26-pred-stopgrad-ablation.md` Task 1.

# /scripts/analyze_pred_stopgrad_ablation.py

## Fixed baseline-arm contamination in `fetch()` (final-review fix wave, Critical finding)

**Before:** `fetch()`'s `--tag` CLI filter was only applied to rows where `arm == TREATMENT`
(`pred_coupled`). `trained`/`frozen` (baseline) rows were pulled from the shared
`condition freeze ablation` wandb group with no tag filter at all. That group actually holds
12 runs, not 9: 3 real `trained` + 3 real `frozen` + 3 real `pred_coupled` (`epochs=100`), plus
one leftover 2-epoch smoke run for each arm (`epochs=2`, run ids `bglo158x`, `7kp3gh5y`,
`fsqcs2ps`). `compute_paired_deltas`'s per-cell `.groupby("arm")[metric].max()` silently
preferred an unfiltered smoke run's inflated `test_oracle`/`test_pre_diff` number over the real
seed-1 `trained`/`frozen` row whenever the smoke run scored higher — corrupting every seed-1
delta and both diagnostic-context (`drift_from_init`, `loss_pred`) rows in the committed report,
and flipping the sign of one metric (`test_pre_diff/i2t_R1` vs. `trained`: reported as a loss,
actually a seed-replicated win once corrected).

**After:** Added `row_passes_filters(arm, tags, epochs, *, treatment_tag, baseline_tag,
expected_epochs)`, a pure predicate factored out of `fetch()` so it's selftestable without a
live wandb call. It applies two independent filters to every row regardless of arm: (1) a tag
filter — `TREATMENT` rows must carry `--tag`, `BASELINE` rows must carry the new `--baseline-tag`
(default `condition-freeze-ablation-redcaps_150k`, 11.1's real tag — deliberately different from
`--tag`'s default, since the two arms were launched by different scripts sharing one wandb
group); (2) an `--expected-epochs` check (default `100`) as defense in depth, applied to ALL
arms, catching contamination even if tag-matching has some other subtle issue. Also added
`warn_duplicate_cells()`, which prints a loud warning naming the run ids involved if more than
one row survives filtering for the same (arm, seed) cell — `compute_paired_deltas` still
aggregates via `.max()`, but the warning now fires so a human notices, rather than the script
working silently either way. Changed `--tag`'s default from `None` to
`pred-stopgrad-ablation-redcaps_150k` (matching `scripts/run_pred_stopgrad_ablation.sh`'s own
`WANDB_TAG` default) so the bare invocation is now the safe one.

**Why:** Final-review finding (Critical), independently confirmed against live wandb —
`docs/superpowers/sdd/2026-08-26-pred-stopgrad-ablation/final-review-fix-report.md`. Downstream:
`docs/reports/2026-08-25_condition_freeze_ablation.md`'s `## Experiment 11.3` section was
rewritten end-to-end from the corrected script output — the corrected data reclassifies the
result from the spec's "reportable instability" branch to its "clean null" branch.
