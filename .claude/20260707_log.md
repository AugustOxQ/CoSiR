## /src/metrics/regularizer.py
Added `refresh_buddy_graph(...)` — rebuilds the buddy CSR from the model's current
combined features (chunked no_grad `model.combine` pass → comb-space `mutual_knn` →
blend a fraction of comb edges with the always-kept frozen CLIP edges →
`build_neighbor_csr`). Returns `(indptr, indices, comb_edges, stats)`; `blend=0`
skips `mutual_knn` and reproduces the CLIP-only CSR. Added `edge_jaccard(...)` (used
for the `graph_churn` diagnostic) and private `_undirected_edge_set`. New imports:
`numpy`, and `mutual_knn` from `src.conditional_buddy.buddy_graph`.

## /src/hook/train_cosir.py
- Imported `refresh_buddy_graph, edge_jaccard`.
- Setup: retained the loaded CLIP edge tensor as `_clip_edge_index`; read five
  `getattr` knobs (`buddy_refresh`, `buddy_refresh_warmup/period/blend/k`); built a
  frozen `combine_feat_table` (combine-side pooled feature in z-order) when refresh
  is enabled (requires `lambda_buddy_con>0` + buddy edges + RAM feature store).
- Epoch boundary: when enabled and `epoch>=warmup` and on period, call
  `refresh_buddy_graph`, rebind `buddy_indptr/buddy_indices`, log
  `graph_*`/`graph_churn` under section `buddy_refresh`.
- Default-off (`buddy_refresh` unset) ⇒ byte-for-byte unchanged.

## scripts/
- `run_buddyrefresh_smoke.sh` — 3-epoch smoke; refresh fires at epochs 1–2.
- `run_buddyrefresh_full.sh` — Hydra multirun sweeping `buddy_refresh_blend ∈ {0,1.0}`
  with #1 off and #2 on; 0 = static #2 baseline, 1.0 = full refresh.

## Final-review fixes (opus whole-branch review)
- **CRITICAL:** `refresh_buddy_graph` now wraps the combine pass in `model.eval()` /
  `model.train(was_training)` (inside `no_grad`, `blend>0` branch only). `no_grad`
  does NOT disable dropout, and the active combiner `Combiner_new` uses `Dropout(0.5)`,
  so without eval-mode the graph was built from dropout-corrupted features. The
  `blend==0` branch is untouched (preserves `blend=0 ≡ Family #2`). Regression test
  `test_refresh_uses_eval_mode_deterministic` added (feature-dependent CPU fake
  `mutual_knn`; asserts two refreshes under `.train()` yield identical graphs) — 7 tests.
- **train_cosir.py setup:** warn when `cfg.train.em_interval>0` (EM alternation can
  desync the refresh schedule) and when `lambda_buddy>0` (Family #1 would share the
  refreshed CSR — out of scope; recommend `lambda_buddy=0`).
- Declined (adjudicated): deduping the unioned edge list — would break the
  `blend=0 ≡ #2` invariant if the CLIP edge list has internal duplicates; mild
  sampling bias accepted instead.

## Ablation tooling + buddy-preservation metric (2026-07-07, post-feature)
- **regularizer.py:** extracted `compute_comb_all_eval` (eval-mode/no_grad full-N
  `model.combine` pass; `refresh_buddy_graph` now reuses it — DRY). Added
  `buddy_knn_preservation(comb_all, indptr, indices, k=10)`: fraction of each node's
  CLIP-E buddies still in its top-k comb-space NN (skips isolated nodes). Tests:
  `src/test/20260707_buddy_refresh/test_buddy_preservation.py` (5, incl. eval-mode
  determinism); refresh suite still 7/7 after the refactor.
- **train_cosir.py:** new default-off flags `log_buddy_preservation` (+`buddy_preservation_k`,
  default 10). When on, buddy edges load even with both lambdas 0, a stable CLIP CSR
  (`_clip_indptr/_clip_indices`) is captured (refresh rebinds `buddy_indptr`, so preservation
  needs its own copy), the combine-side table is built (shared with refresh), and
  `buddy_knn_preservation` is logged under `train_buddy_diag/` at eval cadence for EVERY arm
  (baselines included). Verified via a pure-preservation smoke (lambdas 0 → edges loaded,
  metric fired, 2 epochs, exit 0).
- **scripts:** `EVAL_INTERVAL` env knob (default 100) added to the three `run_buddy*_full.sh`;
  optional `WANDB_TAG` (→ `++wandb.tags`) and `LOG_BUDDY_PRESERVATION` (→ `+loss.log_buddy_preservation=true`)
  on each. New `run_buddy_all.sh` fires all three families (shared tag, 3 groups) tuned for a
  250-epoch first look. New `analyze_buddy_families.py` pulls all three groups from wandb and
  prints paired ΔR1 (t2i+i2t) + per-family activity diagnostics from the NESTED Hydra config.
