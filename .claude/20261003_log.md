# /src/train/train_factors.py

Task 11 (CoSiR v2 CVPR plan): pseudo-aspect episode loss in factor training, default off.

Before (config ends at `condition_beta`; `train_factors` takes `condition_source`, then `history`):
```python
    condition_beta: float = 0.3
...
    condition_source=None,
    history: dict | None = None,
```
After:
```python
    condition_beta: float = 0.3
    lambda_aspect: float = 0.0
    aspect_episodes_per_step: int = 32
    aspect_beta: float = 0.3
    lambda_swap: float = 1.0
...
    condition_source=None,
    aspect_bank=None,
    history: dict | None = None,
```
Also added: validation (aspect_bank required exactly when lambda_aspect > 0; not combined with lambda_condition; bank
rows within 0..n-1), helper `_aspect_tensors`, a `log_tau` init from the step-0 aspect episode scores
(`aspect_rng = default_rng([seed, 2])`, created only when lambda_aspect > 0), the aspect loss term in the epoch loop
and `aspect_loss` / `tau` history entries.

Why: factor training needs a pseudo-aspect episode objective (spec section 6). Every new code path is gated on
`lambda_aspect > 0`, so default runs draw no extra RNG and compute the same loss as before (checked bit-identical on
codes of a default and an R3 tiny run).
