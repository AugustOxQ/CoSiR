# CoSiR architecture rethink: literature review and design brainstorm

**Date:** 2026-09-28  
**Scope:** research and candidate designs only; no implementation or retrieval experiment was run.  
**Hard constraint:** CLIP remains frozen. Every proposed trainable path consumes only its pooled image/text embeddings or projected full token sequences.

## Recommended solution (read first)

**First test a shared, sparse topic router with small topic-specific residual experts on *both* retrieval towers (Candidate A).** Each query modality predicts a distribution over the same inspectable topics; the distribution selects a small number of learned retrieval transformations. This changes both the *condition object* (an auditable sparse distribution, rather than a free per-sample vector) and the *fusion mechanism* (topic-routed transforms, rather than one shallow function of a pooled condition vector). The opposite tower can be precomputed, so the design retains scalable retrieval. Initialize or supervise the topic vocabulary from the buddy student **as one ablation**, and compare against a learned balanced codebook and PercepT-derived topics rather than presuming buddy is best. Train and evaluate using the same query-only condition path at train and test time.

**Run Experiment 18 as the cheap control, not the destination.** Its community-seeded key/value bank and unchanged `CombinerLowRankAdapter` isolate the value of replacing sample IDs with shared topics. If it wins, that still does not show that a single pooled condition plus a rank-16 additive delta is the right final architecture. Candidate B (topic-conditioned token slots) is the highest-upside follow-up if Candidate A's pooled-feature ceiling is visible; it directly tests whether the currently unused CLIP token sequences matter.

The recommendation is a **hypothesis about recall and interpretability**, not an empirical CoSiR result. The recent ArtELingo investigation tested topic formation and topic prediction, **not CoSiR t2i/i2t retrieval**. Its latest correction matters: a symmetrically tuned PercepT Stage 2 mapper scored **0.9226 macro AUC** against buddy's **0.8534**; therefore attention pooling is a strong general mechanism, not a buddy-specific advantage. The older matched-sampling silhouette result (**PercepT 0.4973, buddy 0.0416**) coexists with sharply different held-out occupancy (**21/67 PercepT centers empty versus 0/19 buddy communities**) and a downstream genre probe with a slight **PercepT** edge. None of these metrics alone predicts retrieval gain. The PercepT replication also had two corrected implementation bugs; later fixed-recipe results changed its silhouette and occupancy, so the old 0.4973 figure must not be presented as a clean final PercepT capability estimate. [Project investigation, §§3, 6a–6h](#project-evidence-and-its-limits).

## Current architecture recap

`CoSiRModel` freezes the CLIP-like backbone by default, extracts `img_emb`, `txt_emb` and full image/text token sequences, then combines one chosen pooled side with an external label embedding. The constructor defaults to text, while the checked-in [`clip_base.yaml`](../../configs/model/clip_base.yaml) selects image-side combination. The label encoder is an identity; the effective labels are free parameters keyed by training sample in `TrainableEmbeddingManager`. The other tower has an identity-initialized learnable linear projection. At inference a `ConditionPredictor` MLP estimates a training-style condition from the combine-side pooled embedding; stop-gradient distillation trains that head separately from the free sample vectors. The model itself never obtains a real condition vector for an unseen sample. [`cosirmodel.py`](../../src/model/cosirmodel.py), [`condition_predictor.py`](../../src/model/condition_predictor.py), [`train_cosir.py`](../../src/hook/train_cosir.py).

The present combiners are in a known composed-retrieval lineage: the file header points to CLIP4CirDemo and GeneCIS, while the general problem of gated or residual composition goes back at least to TIRG. `Combiner_new` mixes projected pooled feature and label through an MLP with a scalar gate. `CombinerResidualControl`, `CombinerLowRankAdapter`, and `CombinerFiLMResidual` all output `normalize(feature + delta)`; their last transform/basis is zero-initialized. The low-rank adapter computes coefficients from the label and multiplies a shared 512-by-rank basis, without a feature-dependent expert or token interaction. The `general_full` argument is ignored by these paths. Although `CoSiRModel` can emit full sequences, the checked-in feature-cache configuration disables storage of both image and text sequences; token-based candidates therefore require a new frozen-CLIP extraction/cache run and more storage, not just a new head. [`combiner.py`](../../src/model/combiner.py), [`default.yaml`](../../configs/infra/default.yaml), [`feature_manager.py`](../../src/utils/feature_manager.py); [TIRG, 2019](https://openaccess.thecvf.com/content_CVPR_2019/papers/Vo_Composing_Text_and_Image_for_Image_Retrieval_-_an_Empirical_CVPR_2019_paper.pdf); [CLIP4Cir, 2023](https://arxiv.org/abs/2308.11485).

This creates four structural limits: sample-ID conditions have no shared vocabulary; query-only prediction introduces a train/deployment mismatch; a single 16–32-D vector is a narrow and opaque explanation; and a single pooled CLIP feature cannot select local visual or textual evidence. An identity-initialized other-side projection helps alignment but does not itself solve any of those limits. A higher-capacity combiner alone would leave the condition-source problem intact.

**Historical caution.** The old cluster-conditioning attempt did a contrastive update and then separately pulled already-updated conditions toward UMAP/HDBSCAN/KMeans clusters. The combiner was trained against the pre-pull vectors, so this non-differentiable second step could alter what it consumed without letting it adapt. Experiment 18 correctly moved topic assignment inside the differentiable forward path. The newer investigation also tried multiple DEC-loss hybrids on buddy embeddings; they failed, including a reconstruction-anchored retry after the PercepT implementation fixes. That is strong local evidence against another direct DEC-on-buddy transplant, though it does not rule out all codebook or topic-routing objectives. [`clustering.py`](../../src/model/clustering.py); [Experiment 18 spec](../superpowers/specs/2026-09-15-buddy-prototype-conditioning-design.md); [project investigation](#project-evidence-and-its-limits).

## Project evidence and its limits

The 2026-09-26 ArtELingo report was read in the sibling worktree at `/project/CoSiR-buddy_prototype_conditioning/docs/reports/2026-09-26_artelingo_buddy_vs_percept_stage1_report.md` (it is absent from this checkout). Its most decision-relevant findings are:

- A two-teacher content/affect graph student with one-head self-attention produces normalized 32-D topic features; Leiden gives a frozen community vocabulary. The buddy Stage 1 baseline was competitive on held-out emotion/genre AMI, with 3/4 seeds clearing its declared Pareto bar. k=20 majority-vote transfer put held-out samples onto the *training* community IDs. This validates a topic teacher and vocabulary transfer, **not** a deployable query-only retrieval condition by itself.
- Matched-sampling held-out silhouette was 0.0416 (buddy) versus 0.4973 (the then-current PercepT replication); 19/19 buddy communities were populated, while 21/67 PercepT centers had no held-out points. The same report's later independent review found backwards center pruning and a reconstruction-loss scaling error in the PercepT replication. A corrected faithful-recipe single-seed run reported silhouette 0.2224 and 45/67 centers below 1% occupancy, under a different run/protocol. Thus the original matched number is informative about that audited snapshot, not a universally valid post-fix comparison. Occupancy is also affected by different topic counts.
- A matched image-only downstream probe did **not** turn balanced occupancy into an automatic utility win: genre information retention was 77.2% of a raw-feature control for buddy versus 87.5% for PercepT; emotion was essentially tied and weak for both. This probe was a limited pilot, so it motivates an evaluation dimension rather than a definitive ranking.
- The same single/few-head attention-pooling mapper could learn either topic vocabulary. After symmetric mapper tuning, PercepT achieved 0.9226 versus buddy's 0.8534 macro AUC. The experiment report notes a fresh PercepT fit did not reproduce its earlier untuned starting number exactly. These are **topic-classification** AUCs, with different vocabularies (PercepT 40-way for that Stage 2 comparison; buddy merged to 16); they are not direct evidence of retrieval R@1 and should not be interpreted as a pure architecture ranking.
- Naively upweighting the affect teacher weakened genre AMI without meaningfully improving emotion AMI. The 2026-09-15 condition-space audit also found that apparent warmth and register axes could be explained by content or probe capacity; selectivity must be compared with shuffled-label controls and dimension-matched raw-CLIP baselines. Human-readable labels for a bank require evidence beyond high silhouette or attractive exemplars. [Condition-space audit](2026-09-15_condition_space_audit.md).

## Literature survey

**Composed and controllable retrieval.** [TIRG (2019)](https://openaccess.thecvf.com/content_CVPR_2019/papers/Vo_Composing_Text_and_Image_for_Image_Retrieval_-_an_Empirical_CVPR_2019_paper.pdf) supplied gated residual image/text composition; [CIRPLANT (2021)](https://arxiv.org/abs/2108.04024) used a transformer to modify visual features; and [CLIP4Cir (2023)](https://arxiv.org/abs/2308.11485) popularized CLIP feature composition. CoSiR already inherits this family, so another pooled residual combiner is an incremental baseline, not a clean architectural rethink. [Pic2Word (2023)](https://arxiv.org/abs/2302.03084) demonstrates frozen-backbone projection and zero-shot transfer; it also highlights the query-interface difference: classical CIR has an *explicit* edit caption, while CoSiR must infer a latent condition from one available modality. More recent [FoCo (July 2026)](https://arxiv.org/abs/2607.00374) explicitly learns a focus-then-complete composition process, and [DiCE-CIR (July 2026)](https://arxiv.org/abs/2607.04665) directly trains a lightweight composition module with edit-consistency and discriminability objectives. Both suggest learning the *operation*, not only a condition code. [PACT (September 2026)](https://arxiv.org/abs/2609.31202) adds source-preservation evidence and directional scoring; its preservation idea is relevant to guarding CLIP geometry, though its image/text/edit triplets differ from CoSiR pairs. Reported CIR benchmark gains cannot be imported as CoSiR recall predictions.

**Prototypes and codebooks.** [Prototypical Networks (2017)](https://arxiv.org/abs/1703.05175) motivate stable metric prototypes for generalization; [VQ-VAE (2017)](https://arxiv.org/abs/1711.00937) shows the power and collapse risk of discrete codes. [SwAV (2020)](https://arxiv.org/abs/2006.09882) learns online prototype assignments with cross-view consistency and balanced assignment; [DINO (2021)](https://arxiv.org/abs/2104.14294) and [iBOT (2021)](https://arxiv.org/abs/2111.07832) show self-distillation and patch-level structure, but their encoder-training recipes cannot be copied because CoSiR must freeze CLIP. The transplantable part is a *head-level* shared assignment objective over fixed CLIP features. Balance regularization is a collapse control, not proof that true topics have equal frequency; forcing equipartition could erase rare meaningful modes. The especially direct new [COMBINER (June 2026)](https://arxiv.org/abs/2606.04604) couples cross-modal attribute prototypes with attribute-aware neighbor relations in composed retrieval, supporting a prototype-plus-retrieval architecture rather than prototypes as an isolated interpretability attachment.

**Graph and multiple teachers.** [CoMatch (2021)](https://arxiv.org/abs/2011.11183) uses graph-based contrastive consistency to make neighborhood structure informative to a student. CoSiR's own buddy student is more specific evidence: content and affect graphs jointly supervise a compact topic space. Its success argues for using the graph as a *train-only teacher* or regularizer, then distilling to a query-only encoder; it does not justify querying a train graph with an unavailable opposite modality at deployment. The fixed-vocabulary k-NN transfer is a useful evaluation/control mechanism but is not itself a solution to that query-modality constraint. [GraphSAGE (2017)](https://arxiv.org/abs/1706.02216) is a useful inductive alternative to sample-ID node embeddings, but would require a query-visible neighborhood policy; [FAME-ViL (2023)](https://openaccess.thecvf.com/content/CVPR2023/papers/Han_FAME-ViL_Multi-Tasking_Vision-Language_Model_for_Heterogeneous_Fashion_Tasks_CVPR_2023_paper.pdf) demonstrates multiple-teacher distillation across heterogeneous vision-language tasks including retrieval. Neither paper establishes that CoSiR should expose the train graph at inference.

**Disentanglement and conditional transformations.** [CoSMo (2021)](https://openaccess.thecvf.com/content/CVPR2021/papers/Lee_CoSMo_Content-Style_Modulation_for_Image_Retrieval_With_Text_Feedback_CVPR_2021_paper.pdf) separates content and style modulation in retrieval. [DICE (February 2026)](https://arxiv.org/abs/2602.08059) identifies a content/style subspace through contrastive evidence, though it studies diffusion-model style removal, not retrieval; it supplies an inductive-bias idea, not a validated CoSiR recipe. [FiLM (2017)](https://arxiv.org/abs/1709.07871) and [HyperNetworks (2016)](https://arxiv.org/abs/1609.09106) formalize feature modulation and generated weights; CoSiR already tried shallow FiLM and low-rank residuals. [Sparse MoE (2017)](https://arxiv.org/abs/1701.06538) supplies a materially different option: a code can select among *distinct transforms*, with expert utilization as a visible diagnostic. This is useful only if routing is stable and the experts differ in behavior.

**Attention over sets and tokens.** [Set Transformer (2018)](https://arxiv.org/abs/1810.00825) supplies learned pooling over an unordered set; [Slot Attention (2020)](https://arxiv.org/abs/2006.15055) supplies iterative competition that can yield multiple object-like slots. [PercepT (June 2026)](https://arxiv.org/html/2606.03345) first forms topics from paired factual/affective data and then pools *image patch tokens* with attention to predict topic membership. Crucially, PercepT's Stage 2 is not literally Experiment 18's attention over a bank of key/value prototypes: the former pools tokens and uses topic-specific mapping heads, while the latter pools prototype values from a pooled CLIP query. Both are promising operations, but their reported AUC does not directly validate Exp18's exact bank design. [ColBERT (2020)](https://arxiv.org/abs/2004.12832) is a retrieval-specific reason to retain token-level evidence via late interaction while precomputing gallery features. The modality and index-cost differences must be tested here.

## Candidate architectures

Notation: `D=512` for the current CLIP-B embedding (use the backbone-reported dimension in practice), `K` is a topic count, `r` a small adapter rank, and `T_i/T_t` the frozen image/text token sequences. All learned modules described below sit after CLIP. Each proposal uses a deterministic **single-modality** inference path; paired features, buddy edges, or human labels may supervise training but may never be required to encode a held-out query. For fair t2i and i2t comparisons, precompute the gallery side using only that gallery item's own modality.

### A. Shared sparse topic router with topic-specific dual-tower adapters — **recommended first full test**

**Mechanism.** Learn image and text routers `R_i(img_emb)` and `R_t(txt_emb)` that output calibrated `K`-way probabilities. Keep a frozen inspectable topic vocabulary for the first arm (e.g. 16–32 buddy-derived communities, with merges declared on train only), then separately test an online learned codebook and PercepT-derived targets. For each modality, retain the top 2–3 probabilities as a sparse code `a_m ∈ R^K`. Give every topic a small, modality-specific low-rank expert `E_{m,k}(x)=U_{m,k}V_{m,k}x`; output `normalize(x + g_m(x) Σ_k a_{m,k}E_{m,k}(x))`, with a bounded/zero-initialized gate `g_m`. Both towers are trained with paired retrieval InfoNCE; weak cross-modal code agreement and topic-teacher losses stabilize the shared vocabulary. Regularize *measured* expert utilization and distinctness, rather than mandating exactly uniform use. Per-topic top examples, code probabilities and each expert's actual score contribution are inspectable.

**What it fixes.** It removes the `N × 16/32` sample-ID table and the separate condition-predictor teacher/student gap; conditions for held-out queries come directly from `R_m`. It also replaces the one-vector-to-one-delta bottleneck with several identifiable, feature-dependent transforms. It still relies on pooled CLIP evidence and will miss local details. Literature grounding: [SwAV](https://arxiv.org/abs/2006.09882) for shared assignments, [COMBINER (2026)](https://arxiv.org/abs/2606.04604) for attribute prototypes plus neighbor relations, [CoMatch](https://arxiv.org/abs/2011.11183) for graph supervision, [HyperNetworks](https://arxiv.org/abs/1609.09106) and [sparse MoE](https://arxiv.org/abs/1701.06538) for code-selected transformations.

**Trade-off and relationship to Exp18.** Highest balanced bet: plausible recall gain from per-topic operators and symmetric alignment, with a genuinely audit-friendly condition distribution. It is **more than** Exp18's contained bank-plus-unchanged-low-rank swap: the training loop, both towers, optimizer, checkpoints and t2i/i2t evaluation paths change. Risks are expert collapse, accidental content-only routing, code-agreement pressure erasing legitimate modality differences, and the non-identifiability of topic names. Buddy topics are an initialization/teacher, not a required component. The tuned PercepT Stage 2 reversal argues for equal mapper optimization and a PercepT-target ablation; it says nothing about which router improves recall.

### B. Topic-conditioned token-slot composer — **highest local-detail upside**

**Mechanism.** Project masked `T_i` and `T_t` tokens into a common small hidden width without changing CLIP. Maintain `K` shared topic queries (`K × d`). For each modality, one or two cross-attention/Slot-Attention-style rounds yield `K` sample-specific slots (`K × d`) and token attention maps; a sparse topic selector chooses a few slots. A gated head combines selected slot outputs with the modality's original pooled embedding to produce one normalized, indexable `D`-vector. Pairwise retrieval loss trains the heads, while optional topic-teacher distillation aligns slot IDs across modalities. The test query uses only its own token sequence; each gallery item's final vector is precomputed independently. A small version can use one pooling head before considering iterative competition.

**What it fixes.** It removes free per-sample conditions, represents condition as a *set of active topic slots* rather than one vector, and uses the full token sequences CoSiR can extract but does not cache by default. It may distinguish similar scenes whose relevant attribute appears in one patch or phrase. [PercepT](https://arxiv.org/html/2606.03345) provides direct local evidence that attention pooling over image patches can predict topics; [FoCo (2026)](https://arxiv.org/abs/2607.00374) motivates focus before composition; [Slot Attention](https://arxiv.org/abs/2006.15055) supplies multi-slot competition. No buddy dependency is necessary: learned slots can be tested against buddy/PercepT-seeded slots. PercepT's Stage 2 reversal reinforces token pooling as a generic mechanism, not the value of any particular teacher.

**Trade-off.** Potentially the best recall upside if pooled CLS discards relevant detail, and token maps provide candidate explanations. A map is *not* automatically a faithful explanation: verify by masking top-attended tokens and showing score changes, and by topic exemplars. Complexity is high relative to Exp18: frozen-CLIP token re-extraction and caching, padding/mask handling (especially text), modality-specific sequence lengths and projections, plus new training and evaluation plumbing. Frozen CLIP patch tokens may not be reliably local or comparably aligned to word tokens. A token-free version of the same head is the essential ablation.

### C. Experiment 18 prototype-pooling swap — **cheap diagnostic control**

**Mechanism.** Use the proposed `P` community-seeded learnable key/value pairs in a 16-D condition space. Map the pooled combine-side CLIP feature to a query, softmax over keys, and pass the value-weighted sum into the *unchanged* `CombinerLowRankAdapter`; keep its identity-initialized residual. Train bank, query projection and combiner jointly with retrieval and existing buddy-consistency losses. A held-out query uses the same pooling path, so no per-sample vector or separate predictor is needed. Frozen train Leiden IDs can seed/label the bank; inspect attention weights and prototype exemplars. [Experiment 18 spec](../superpowers/specs/2026-09-15-buddy-prototype-conditioning-design.md), [Prototypical Networks](https://arxiv.org/abs/1703.05175), [PercepT](https://arxiv.org/html/2606.03345).

**What it fixes and leaves.** It directly solves sample-ID memorization and condition availability for unseen samples, while preserving the existing combiner interface. It does **not** test richer feature-conditioned fusion, use full tokens, or make the low-rank basis topic-specific. Soft attention over values can average distinct topics into another opaque 16-D vector; report both its probabilities and the pooled result. It is the most contained experiment by design, but still needs embedding-manager persistence and inference/evaluation wiring. Interpretability is medium only if bank use, held-out occupancy and stable human topic names check out. Prototype collapse is a specific risk; SwAV-style balancing is a possible ablation, not an automatic fix. The 0.9226 versus 0.8534 Stage 2 finding argues against assuming buddy-seeded keys will be superior to other seeds.

### D. Factorized content/affect code with controlled composition — **interpretability-focused, higher identification risk**

**Mechanism.** Instead of a single topic bank, learn `K_c` content codes and `K_a` affect/attribute codes from the same frozen CLIP pooled inputs. A query-side router produces two sparse distributions; the output is `normalize(x + δ_content(x,a_c) + δ_affect(x,a_a) + δ_interaction(x,a_c,a_a))`, with only a low-rank interaction term so the full `K_c × K_a` Cartesian table is unnecessary. Use the project's two teacher graphs to give *weak* content and affect supervision on train samples; route held-out queries from CLIP alone. Swapped-pair or matched-content controls test whether changing an affect code leaves content retrieval stable. Inspect the two codebooks separately, plus their joint occupancy.

**What it fixes.** It supplies an explicit, compositional condition structure rather than hiding content and feeling in one vector. It can express multiple readings of similar visual content. [CoSMo](https://openaccess.thecvf.com/content/CVPR2021/papers/Lee_CoSMo_Content-Style_Modulation_for_Image_Retrieval_With_Text_Feedback_CVPR_2021_paper.pdf) is directly relevant to retrieval; [PercepT](https://arxiv.org/html/2606.03345) separates factual/affective aspects; [DICE (2026)](https://arxiv.org/abs/2602.08059) suggests contrastive subspace controls but is in a different task. Existing CoSiR FiLM can serve as the simplest transform ablation.

**Trade-off.** Potentially the most human-readable condition and a way to distinguish content from subjective framing, but recall upside is uncertain. The project's 17.1 audit showed that some apparent affect axes were content-confounded, and simply increasing affect-teacher weight harmed buddy genre AMI. Without matched-content labels or interventions, factor names may be wishful labels on entangled codes. More training infrastructure than Exp18: two teachers/codes, joint objectives, controlled swaps and separate probe reporting. A strong failure mode is retrieval learning to ignore the affect bank while still producing attractive visualizations.

### E. Topic-weighted token late interaction — **retrieval-ceiling probe with index cost**

**Mechanism.** Stage 1 uses a standard pooled CLIP/CoSiR query to fetch top `M` candidates. A query-only topic router supplies sparse weights over a small bank; a lightweight head uses them to weight/project the frozen query tokens. Gallery token vectors require a new frozen-CLIP extraction/cache pass and are then precomputed once. Stage 2 scores each shortlisted pair with a topic-weighted `Σ_query-token max_gallery-token cosine` (or a small learned symmetric analogue), with a pooled-score fallback. Train with positive pairs and hard negatives; retain top-token correspondences and topic contribution as inspectable evidence. No paired modality is needed to form the query condition. [ColBERT](https://arxiv.org/abs/2004.12832) grounds late interaction, [FoCo (2026)](https://arxiv.org/abs/2607.00374) motivates focusing relevant evidence, and [PACT (2026)](https://arxiv.org/abs/2609.31202) motivates preserving source evidence.

**What it fixes.** It abandons the requirement that all conditional evidence fit one 512-D retrieval vector and uses the full sequences. Topic weights still provide shared condition structure, though token matches are less semantic than labeled prototypes. It can improve **R@1 within the first-stage shortlist** but cannot recover a true target absent from top `M`; report that ceiling. The index, memory and latency changes are much larger than Exp18's swap, and training/evaluation become two-stage. Cross-modal CLIP token spaces may be less aligned than their pooled outputs. Buddy or PercepT topics are optional router teachers; the Stage 2 classifier AUC does not validate token matching quality.

## Comparison and ranking

These are **qualitative priors, not measured gains**. “Infrastructure” is relative to Experiment 18's condition-source swap; all rows keep CLIP frozen.

| Rank | Candidate | Expected retrieval upside | Condition interpretability | New infrastructure | Main decision risk |
|---:|---|---|---|---|---|
| **1** | **A: sparse topic router + dual adapters** | Medium–high | High if usage and contributions validate | Medium–high | Router/expert collapse or topic labels following content only |
| **2** | **B: token-slot composer** | High if local evidence matters | Medium–high with faithfulness tests | High | CLIP token quality and attention-as-explanation gap |
| **3** | **C: Exp18 pooled bank** | Low–medium | Medium | Low–medium | Better topics but same shallow retrieval operation |
| **4** | **D: factorized content/affect** | Medium but uncertain | Potentially highest | High | Unidentifiable factors without stronger controls |
| **5** | **E: topic-weighted late interaction** | High *within shortlist* | Medium | Very high | Recall ceiling, token index and serving cost |

Candidate C should run **before** A if the immediate objective is to measure the value of a shared condition source at minimal cost; its lower rank reflects expected *next-generation architecture* value, not experimental priority. A versus B is genuinely unresolved: A is the better balanced first design because it changes both condition structure and transformation while keeping a single-vector index; B may win if local details, rather than code structure, are the dominant bottleneck. E is useful if a two-stage serving contract is acceptable and first-stage top-`M` recall is already high. D becomes more compelling if human affect labels or matched-content controls are available.

An efficient comparison isolates causes: frozen-CLIP baseline; current free-vector + `CombinerLowRankAdapter` baseline with both **oracle** and **query-only predictor** scores; C (source change only); single-side A with the same topic source (routed transform only); full dual-tower A (symmetry added); and B with its own token-free ablation (token access isolated). Compare buddy, corrected-PercepT and learned-bank teachers with the **same router capacity and tuning budget**, not their historical Stage 2 AUCs. Use at least three paired seeds and a predeclared practical R@1 margin. Keep t2i and i2t separate, report R@1/R@5, and compare equal gallery/index setups. A gain only in oracle conditioning, or only in topic-classification AUC, is not a deployable retrieval win.

## Open questions / what needs real experiments

1. **Does topic structure help retrieval at all?** Compare C with the current query-only baseline, random/shared prototypes, a no-condition residual head, and the current oracle upper bound. A shared bank could improve AMI while degrading recall; this is the primary unknown.
2. **Which topic teacher transfers to CoSiR's data?** The ArtELingo result is task/dataset-specific. Rebuild vocabulary on each training split only, map validation/test using one modality, and evaluate buddy, corrected PercepT and learned-bank controls under equal `K` where feasible. Examine empty/rare topics, effective topic count, topic entropy, AMI where human labels exist, and outcome-probe utility; do not select by silhouette alone. PercepT's corrected replication and run-to-run drift require a fresh pinned comparison.
3. **Is the inference path truly the training path?** Distill or train query-side routers directly and score them in-loop, rather than optimizing retrieval with paired/oracle conditions and reporting only a later predictor. For both directions, freeze the topic vocabulary on train and forbid held-out paired features or test-set k-NN neighborhoods from entering an individual query condition. Keep the fixed-vocabulary k=20 transfer as a diagnostic, not a hidden inference oracle.
4. **Does fusion, rather than condition quality, bind recall?** A single-side A variant with C's identical topic source isolates routed experts, then adding the second tower isolates symmetry; B versus its token-free ablation isolates token access; a zero-delta control checks whether improvements arise from the learned other-side projection or retrieval training alone. For B/E, verify CLIP token projections, text padding masks, token storage and top-`M` ceiling before large runs.
5. **Can people trust the condition explanation?** Reuse [`condition_space_evaluator.py`](../../src/utils/condition_space_evaluator.py)'s silhouette machinery, but score in the actual deployed code space and report occupancy beside it. Reuse the [17.1 selectivity-gated probe protocol](2026-09-15_condition_space_audit.md): shuffled-label controls, effect-size floor, content-matched controls and dimension-matched raw-CLIP baselines. Add held-out exemplar annotation, cross-seed topic matching, code intervention/ablation and actual ranking-change attribution. Attention maps and prototype names alone are insufficient.
6. **How much capacity is justified?** Compare topic count, **16-D versus 32-D condition capacity**, top-k routing, adapter rank, token-slot count and single versus dual tower under matched compute. The ArtELingo width sweep found larger topic embeddings traded emotion for genre and did not improve separation; capacity should be chosen by retrieval-plus-coherence evidence, not by defaulting upward.

**Decision rule:** advance a candidate only if its *query-only* t2i or i2t recall gain is reproducible and exceeds the project's predeclared noise/practical margin **and** its held-out condition vocabulary is populated, stable, and more interpretable under controlled probes than the free-vector baseline. Report a null on either axis honestly; a high Stage 2 AUC, silhouette, or oracle recall alone does not meet the joint objective.
