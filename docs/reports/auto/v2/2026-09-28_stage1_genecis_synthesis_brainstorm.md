# CoSiR v2: from validated topics to open conditional image–text similarity

**Date:** 2026-09-28  
**Scope:** literature review and design hypotheses; no model was trained and no retrieval result is claimed.  
**Decision boundary:** the ground-up rewrite and the Attention-h1 buddy-graph topic-formation Block 1 are settled in the [redesign spec](../../../superpowers/specs/2026-09-28-cosir-v2-ground-up-redesign.md). This report advises what to investigate above that block.

## Recommended direction

**Keep the validated Stage 1 as a graph and community *prior*, but do not make its `K` community IDs the conditions. Replace the classification-shaped Stage 2 with a shared image–text factor layer and an explicit, selectable condition interface.** The first Block 2 experiment should learn sparse factors that have corresponding activations in both modalities, using paired frozen CLIP features and Stage 1 neighborhoods as candidate structure. A condition should select a sparse mixture of those factors from a few *support examples* (with contrasts when the intended aspect is ambiguous). The retrieval score must compare an image and a text under that same selected mixture, in either direction. Training episodes must contain condition-swapped hard negatives so that ignoring the condition cannot minimize the loss. **Before treating this as the Block 2 design, settle whether automatically sampled, temporary pseudo-labeled episodes meet the project's “no structured/labeled dataset construction step” boundary.** Also test whether the factor layer works without Stage 1's supervised GoEmotions-derived affect graph; otherwise the “unsupervised” differentiator must be narrowed.

This is a **research hypothesis, not a demonstrated CoSiR result**. Stage 1's held-out AMI and occupancy validate topic formation; they do not validate factor discovery, condition selection, or conditioned retrieval. A fixed factor dictionary could support unseen **mixtures** of learned factors, but it cannot honestly claim arbitrary new primitives. If that limitation is decisive, a graph-local, support-induced metric is the second candidate below. Both designs need an external condition input. A model that receives only an image or only a caption cannot infer which of several equally valid notions of similarity the user wants for that *same* query.

The earlier [Candidates A–E memo](2026-09-28_architecture_rethink_literature_brainstorm.md) addressed free vectors, asymmetric fusion, and weak retrieval. Its query-only sparse router remains a useful **unconditioned baseline**, but `c = router(query)` is fixed once the query is fixed. It therefore does not by itself solve GeneCIS's dynamic-condition problem. The new designs add a condition argument `c` to the *image–text comparison*, not merely a better per-query representation.

### What the target task must mean

Write the task as `s(I,T | c)`, where `I` is an image, `T` is a caption/text, and `c` is an independently supplied condition. For image-to-text, rank `T` for fixed `(I,c)`; for text-to-image, rank `I` for fixed `(T,c)`. The decisive test holds the image, candidate captions, and gallery fixed while changing `c`, then looks for a justified ranking reversal; repeat with the caption as anchor. Ordinary paired CLIP retrieval scores `s(I,T)` and cannot express this test. Topic classification returns `p(k | I)` or `p(k | T)` and does not score the conditional *relation* between the two. A text condition is a third input, even when the retrieved item is also text.

**Primary retrieval task:** cross-*item* aspect matching, the direct cross-modal analogue of GeneCIS focus similarity. For example, given an image of a red car, a condition “shared color” should rank a caption about a red bicycle above one about a blue car; under “shared object/category,” the order should reverse. The candidate caption describes its *own* item, not necessarily the query image. A relevant image–caption pair shares the property selected by `c`, as judged independently for the evaluation set; distractors may share another property or only match `c` without matching the query. This requires a purpose-built, human-judged conditional image–text evaluation set with both retrieval directions and multiple valid positives. It is **not** the usual “retrieve this image's paired caption” task. Selecting among different captions of the *same* image is a separate, secondary grounding/ambiguity diagnostic—useful on ArtELingo, but it cannot stand in for the primary cross-item result.

“Unsupervised condition discovery” here means **no condition taxonomy or condition labels used to train CoSiR**. Natural image–caption pairing, the pretrained CLIP representation, the choice of content/affect graph teachers, graph neighborhoods, sparsity, and support-example format are substantial inductive biases. They should be reported openly. Perfectly identifiable human semantic factors cannot be inferred from unstructured observations alone; the [disentanglement impossibility result](https://arxiv.org/abs/1811.12359) is a reason to test the discovered axes with independent judgments, rather than name them from attractive exemplars.

There is a further design constraint: **ordinary paired-image/text InfoNCE alone cannot teach a model which of several valid relations should win after `c` changes**. The proposals therefore generate temporary support/query episodes from graph and factor structure. This is automatic self-supervised *training-task construction*, not a stored condition-labeled corpus or a hand-coded condition taxonomy. Whether those temporary pseudo-labels satisfy the requirement is an **unresolved design decision**, not a semantic loophole. If “no structured dataset construction” is meant to forbid even these episodes, the requirement conflicts with training a selectable conditional ranking rule from the available pairs; some other source of condition variation or relevance feedback would be needed.

## GeneCIS method detail and the precise departure

[GeneCIS](https://arxiv.org/html/2306.07969) defines conditional similarity as `f(I_target; I_reference, c)` with a **user-specified text condition**. CLIP encodes both images and the condition. A Combiner composes reference-image and condition embeddings; its dot product with the target-image embedding is trained with in-batch contrastive loss. At inference, the text condition can be a previously unseen phrase; the architecture has no classifier whose output must be one of `K` condition labels. It still ranks **images against images**. CoSiR's [`combiner.py`](../../src/model/combiner.py) credits GeneCIS's implementation directly.

The paper's training-data mining is more open than the shorthand “hand-designed condition taxonomy” suggests. Starting with ordinary CC3M image–caption pairs, an off-the-shelf scene-graph parser extracts subject–predicate–object relations. A human-rated visual-concreteness lexicon filters poor visual entities. Two images sharing a subject but having different objects form reference and target; the **target predicate plus object** becomes the text condition. The authors mine about 1.6 million triplets and train on those, with a noted bias toward “change object” relationships. This is automatic, open-vocabulary condition *mining*, but it depends on engineered linguistic structure and an external human-rated filter. It is not label-free discovery of the condition axes themselves. [GeneCIS §5](https://arxiv.org/html/2306.07969).

GeneCIS's **evaluation benchmark**, distinctly, is a designed `focus/change × attribute/object` grid: four tasks built using VAW attribute annotations and COCO Panoptic object annotations. “Spatial relation” can occur in mined predicates, but it is **not a fifth formal benchmark category**. Each task uses a 10–15-image curated gallery, typically with one designated positive and distractors that match only the reference or only the condition. This design directly tests whether the condition matters; the paper also acknowledges annotation noise and possible alternate valid targets. Its “zero-shot/open-set” claim means no fine-tuning on these evaluation conditions and flexible text phrases; it does not prove unlimited condition semantics. The strongest GeneCIS model fine-tunes CLIP; freezing the entire backbone reduces its reported average GeneCIS R@1 from 16.8 to 15.1, so CoSiR's frozen-backbone rule is a material constraint. [GeneCIS §§4–7](https://arxiv.org/html/2306.07969).

For CoSiR, the two departures are thus precise: (1) learn usable condition factors from paired-feature/graph structure without GeneCIS's scene-graph parser or concreteness lexicon, and without importing its **evaluation** task grid as training labels; (2) use `s(I,T|c)` rather than `s(I_reference,I_target|c)`. GeneCIS also notes that “change” conditions are directional. A focus-style cross-modal match can use a symmetric score under fixed `c`, but a future “change” operator may need separate source and target roles rather than an enforced symmetry. The first experiment should focus on aspect selection, then test directional transformations explicitly. This report's corrected GeneCIS account supersedes the shorthand description of GeneCIS in §4 of the framing spec; it does not alter that spec's settled Block 1 decision.

## PercepT and the validated buddy Stage 1

[PercepT](https://arxiv.org/html/2606.03345) defines a perception topic as a cluster of **image–caption pairs** sharing factual and affective characteristics. Its factual representation fuses CLIP image and caption embeddings; its affective representation comes from a GoEmotions-tuned text encoder. The paper chooses those two axes in advance, then discovers their *combinations* as topics. It pretrains a denoising autoencoder, sharpens Student-t soft cluster assignments with a DEC KL objective while retaining reconstruction, starts with `K₀ = 100`, and prunes high-norm centers with a gap heuristic. Its Stage 2 pools image patches with attention and uses binary cross-entropy to predict which discovered topics apply to a new **image**. These are topic labels derived from Stage 1, not cross-modal conditional retrieval targets. The paper's 0.94 Stage 2 AUC measures this mapping task. [PercepT §§3–5](https://arxiv.org/html/2606.03345).

CoSiR's validated **Attention-h1** is a different Stage 1: a cross-modal mutual-kNN buddy graph, content and affect teacher graphs, symmetric InfoNCE student training, one-head attention fusion, LayerNorm and L2-normalized output, then community formation. The project investigation (`docs/reports/auto/percept/2026-09-26_artelingo_buddy_vs_percept_stage1.md`, present as an uncommitted file in the sibling worktree for `experiment/percept_topic_pipeline`) reports competitive held-out human-label AMI and all 19 buddy communities populated in one matched audit, versus 21 of 67 PercepT centers empty in that audited replication. Its same report records PercepT's stronger silhouette and, in a limited genre probe, a slight PercepT edge; it also documents replication corrections. Those measures answer different questions. The report's older symmetrically tuned Stage 2 snapshot favored PercepT (0.9226 vs 0.8534 macro AUC); the current 55+ gate-passing configuration sweep is preliminarily favoring buddy and is still pending stress confirmation. Neither snapshot is retrieval evidence.

PercepT provides a useful warning as well as a precedent: multi-aspect, paired-modal topics can emerge without direct topic labels, while a highly effective topic assigner can still stop one conceptual step before conditional similarity. Its factual/affective split is itself a design prior, and its GoEmotions encoder carries supervised affect knowledge. **The Attention-h1 reference implementation also extracts caption-derived 28-dimensional probabilities from a GoEmotions-trained model for the affect teacher graph; no ArtELingo emotion label is passed as an input, but an external supervised emotion taxonomy enters the features.** This was verified in `run_learned_student_arch_sweep_pilot.py` (the `extract_affect_nodes` calls and affect-graph construction). Any claimed *discovered* affect axis must survive an affect-teacher removal/replacement ablation. CoSiR can retain the useful two-teacher graph geometry without asserting that the resulting community IDs are disentangled “condition types.”

The evidence points to a missing conjunction rather than an off-the-shelf answer: **shared discovered factors**, **externally selectable conditions**, and **bidirectional image–text scoring with frozen CLIP** have each been explored in adjacent work, but the papers above do not validate their combination for CoSiR. In particular, “open-set” cannot be inferred from a large `K` or from softmax probabilities over `K` topics.

## Candidate A — graph-guided shared factors plus support-conditioned cross-modal score (first test)

**Discovery.** Run the settled Stage 1 on training pairs only. Preserve its normalized student embedding, graph neighborhoods, and frozen Leiden communities as a *sampling hierarchy*: community, local neighborhood, and cross-community overlaps. Learn two small post-CLIP factor encoders `a_I(I), a_T(T) ∈ R⁺^L` with a shared factor index. Paired image/text activations should agree where a factor is shared, while modality-private residual capacity can retain evidence that has no honest counterpart. Sparse reconstruction of frozen features, paired activation agreement, and graph-neighbor consistency are candidate self-supervised losses. For the strictest discovery claim, use only the content buddy graph to mine factor episodes and compare it with full Stage 1 guidance; otherwise supervised GoEmotions structure can propagate into the factors. A group-sparse/masking or sparse-CCA control is needed so an apparently shared dictionary does not merely split into image-only and text-only units. Whole-community IDs supervise **where to look**, not what each factor must mean. Test whether useful factors span multiple communities; if they do not, the construction has just renamed topics. This is inspired by [MGSAE](https://arxiv.org/abs/2601.20028), [LUCID-SAE](https://arxiv.org/abs/2602.07311), and [SCoCCA](https://arxiv.org/abs/2603.13884), not an established CoSiR recipe.

**Condition interface.** At inference the user supplies a few examples of the desired relationship: matched image–text *support pairs*, ideally with contrast pairs that differ in the aspect to attend to. A set encoder estimates sparse weights `w(c) ∈ R⁺^L` from the factors **shared by the positive supports but absent from the contrasts**, with uncertainty when several explanations remain. This supports a new mixture of discovered factors without a name or training-set condition label. To test GeneCIS's *text-prompt* interface as well, map a novel condition phrase directly through the text factor encoder (`w(c) = a_T(c)`, calibrated), or retrieve support pairs with frozen CLIP and apply the set encoder. Neither route is validated: a factor encoder trained on descriptive captions may not understand an abstract aspect name such as “color.” Report prompt-only and support-conditioned zero-shot results separately; they are different claims. A single plain matched pair may be ambiguous (content, tone, style all co-occur); contrast supports are a semantic input, not a hidden label. Stage 2's attention pooler might initialize a modality-specific factor encoder, but its `K`-way classification head is not the new condition mechanism.

**Cross-modal comparison.** A minimal symmetric focus score is

`s(I,T|c) = β · cos(CLIP_I(I), CLIP_T(T)) + Σ_l w_l(c) · a_I,l(I) · a_T,l(T)`, with calibrated normalization and a separately tested pair-interaction head only if needed.

The same `w(c)` weights image and text evidence in both t2i and i2t; candidate-side factor codes can be indexed once. The raw-CLIP term retains a baseline semantic signal but **does not guarantee** raw-CLIP recall: a badly weighted factor term can reverse correct rankings. A factor active only in a caption cannot by itself make that caption a good match for an unrelated image. Conversely, if the image cannot distinguish several subjective readings and activates them all, the score may reduce to condition–caption matching. If score calibration shows private factors leaking into shared comparison, mask them out.

**Loss that makes conditions causal.** Sample self-supervised training *episodes*, not a permanent taxonomy-labeled triplet dataset. Use a **frozen/stop-gradient snapshot** of discovered factors and graph neighborhoods to propose a support set and a held-out cross-*item* query pair; update the scoring model against these episodes, then refresh the miner on a slower schedule and on disjoint data. This prevents the same step from changing its own pseudo-labels, though it does not make them ground truth. Choose hard distractors matched in global CLIP similarity and often in Stage 1 community, but differing on the selected factor. Optimize bidirectional conditional InfoNCE/ranking for `s(I,T|c)`. In the same episode, choose another valid factor mixture `c′` for the **same anchor and candidate pool** and require the appropriate positive to change; add an explicit swap margin or rank-order loss. The positive support items must be disjoint from scored query/gallery items. Include condition-only and anchor-only distractors, as GeneCIS does. A no-condition model should fail the swap test even if it has excellent ordinary pair recall. Factor-based pseudo-labels still risk circular self-confirmation, so condition-blind and random-factor controls plus independently judged held-out tests are mandatory.

**Open-set claim and limit.** Hold out combinations of factors and support sets during training; test them with no gradient updates. This is a plausible **compositional open set** within a finite basis, including continuous weightings and multi-aspect conditions. It is not evidence of a new semantic primitive absent from training data or absent from frozen CLIP. The hardest empirical risks are discovering topic/content proxies instead of aspects, support ambiguity, pseudo-label leakage, one modality's factors dominating, and reverting to the old Mean-JSD-zero ranking behavior despite attractive factor plots.

## Candidate B — support-induced graph-local metric (nonparametric alternative)

This candidate asks whether the graph itself can supply a condition **without** treating either communities or a learned `L`-factor dictionary as a closed vocabulary. Keep Stage 1's paired-image/caption student and its graph **on the training set**. Because Attention-h1 itself consumes paired content and caption-derived affect, it cannot directly embed a held-out image-only or text-only query. Train separate image-only and text-only attachment heads to predict train-graph neighborhood distributions from each modality's own frozen CLIP feature; a Stage 2 image classifier is not a text attachment head. Validate these heads against held-out paired neighborhoods before using them for retrieval. At inference, attach positive/contrast support examples through these heads, propagate a signed relevance signal through local buddy edges, and derive a condition-specific neighborhood measure. Attach the query image and each candidate caption independently to this same graph. Score their cross-modal compatibility from how strongly their neighborhoods overlap **under the support-induced measure**, plus calibrated raw CLIP similarity. Reverse image and text roles for i2t. No query may use its hidden paired modality, and no test item may become a training graph node.

Training can meta-learn attachment, propagation depth, and image/text calibration through leave-neighborhood-out episodes with condition swaps and within-neighborhood hard negatives. The support examples define `c` on demand; there is no fixed list of condition IDs, and new local combinations can be represented without retraining. This is genuinely cross-modal if the final score compares an independently encoded image and caption and both directions pass the swap test. It is **not automatically open to arbitrary semantics**: a condition unsupported by frozen CLIP geometry or training-graph coverage has no reliable path. It also has graph-storage, latency, and hub/degree-bias costs, and can collapse to a fancy topical nearest-neighbor score. It is the cleaner fallback if Candidate A's shared factor dictionary proves unstable, but likely the less scalable first system.

## Stage 1 role: preserve formation; change what its outputs mean

**Verdict:** Block 1 is a defensible foundation and should be rebuilt as decided. Its positive evidence is real and stronger than the evidence for any Block 2 design. But the Stage 1 community partition is **not** a condition ontology. A topic may bundle factual content and affect, and a useful condition such as tone, material, viewpoint, or relation may cut across many topics. Making `topic ID = condition` turns the task back into fixed-`K` classification; taking soft mixtures of those IDs increases the number of combinations but does not guarantee the components are meaningful axes. Stage 1 should supply graph geometry, multi-resolution neighborhoods, training episodes, and interpretability probes. Candidate A asks a new factor layer to extract reusable axes within/across those neighborhoods; Candidate B uses the graph directly as a conditional support kernel.

The current Stage 2 attention classifier is worth retaining only as an **auxiliary probe or initialization**: does a single-modality query recover Stage 1's train-defined topics? Its high macro AUC cannot certify `s(I,T|c)`. A query-only router from the earlier memo likewise remains a fair baseline, but unless a distinct condition input can change the same query's rankings, it does not meet the target. Conversely, if condition-weighted factor or graph scores fail while plain conditioned text/pair scoring succeeds, the right conclusion may be to keep Stage 1 for topic analysis and decouple the retrieval system from it. The settled Block 1 does not commit Blocks 2+ to using its communities as model outputs.

## Open questions and experiments that would decide

1. **Can conditions be identified from available data?** Build a dedicated, human-judged **cross-item** image–text condition-swap set for the primary task. On ArtELingo, separately use held-out images with multiple, genuinely different captions as a *same-image grounding diagnostic*; do not count it as cross-item retrieval. Train CoSiR without ArtELingo emotion/genre/condition labels; use those labels and blinded human judgments **only for evaluation**, while separately disclosing the supervised GoEmotions prior in Stage 1. Compare factor stability across seeds, support-set perturbations, cross-community recurrence, and raw-CLIP/dimension-matched controls. The [condition-space audit](../buddy/2026-09-15_condition_space_audit.md) found that warmth was mostly explained by content with only a small residual, while register lacked convincing extra signal; probe names need controlled evidence.
2. **Does the condition change rankings for the right reason?** Predeclare paired `c`/`c′` episodes with the *same anchor and gallery* and independent relevance judgments. Report swap accuracy, top-`k` JSD/diversity, condition-ablation drop, and examples of valid/invalid flips alongside t2i and i2t Recall@1/5. A high JSD alone could represent arbitrary instability; Mean JSD near zero repeats the current architecture's known failure. Run condition-only, query-only, plain CLIP, trained dual-tower, random-factor, shuffled-support, Stage2-topic, and Candidate A/B controls.
3. **What does “zero-shot” generalize over?** Freeze model and train graph before evaluation. Hold out compositional condition mixtures, support exemplars, concepts, and preferably a domain; report each separately. A held-out mixture of seen primitives tests recombination, while an unseen primitive tests a harder claim that Candidate A may fail. Because CLIP is pretrained, “unseen concept” usually means unseen in **CoSiR training**, not necessarily unseen to the backbone; use post-pretraining data or an auditable novelty protocol before claiming the latter, as [ZeroSight](https://arxiv.org/abs/2606.07032) emphasizes. Train-only mining and support/query disjointness prevent leakage. Existing CIR or product benchmarks have different target modalities and can only supply *adapted diagnostics*, not an off-the-shelf `s(I,T|c)` test; their taxonomies must not enter training.
4. **Can pseudo-episode mining avoid circular success?** Quantify false negatives and graph homophily. Vary hard negatives: same topic/different factor, same factor/different topic, high raw-CLIP similarity, and condition-only matches. Score independent human relevance, not only agreement with the very factors used to create training positives. GeneCIS's small galleries and [ZeroSight's evaluation critique](https://arxiv.org/abs/2606.07032) motivate both curated adversarial galleries and full-gallery results with multiple acceptable positives.
5. **Does frozen pooled CLIP contain the required local evidence?** First test pooled Candidate A against the same architecture without conditions. If aspect binding fails despite real factors, compare token/patch variants informed by [LUCID-SAE](https://arxiv.org/abs/2602.07311) or [FLAIR](https://arxiv.org/abs/2412.03561); that requires a new frozen-token cache and should be justified by a measured pooled-feature ceiling. GeneCIS's frozen-backbone ablation warns against assuming its gains transfer unchanged.
6. **What is the success gate?** Reproduce gains across paired seeds and both retrieval directions against raw CLIP and the best condition-blind trainable baseline, while preserving Stage 1's held-out topic quality and demonstrating nontrivial, human-supported condition swaps on held-out conditions. On subjective captions, require a gain over the condition-only scorer to show the image contributes; otherwise the affective cross-modal claim fails even if recall rises. AUC, AMI, silhouette, occupancy, factor reconstruction, and oracle-conditioned retrieval are supporting diagnostics. None substitutes for deployable, explicit-condition cross-modal ranking.

**Recommendation after this review:** use the cross-item, support-conditioned **focus** task defined above as the first Block 2 target, with a new human-judged condition-swap evaluation set. Decide explicitly whether temporary self-mined episodes are within the no-dataset-construction constraint. Then test Candidate A with content-only buddy guidance, full Stage 1 guidance, and an independently trained shared-factor baseline; use Candidate B if fixed factors cannot retain stable cross-modal meaning. Test free-text conditions as a separate GeneCIS-interface transfer claim. This preserves the one validated block while making the actual GeneCIS-derived question experimentally falsifiable.
