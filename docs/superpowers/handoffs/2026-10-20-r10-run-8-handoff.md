## 5. Code and pitfalls

- **Run from `/project/CoSiR`.** `ct2_run.py` writes to its own round folder (`outputs/stage2/`, reports beside the
  rule), and stage 1's artifacts are read from the main checkout. A run from a worktree writes into the worktree.
- **The stage 2a pass binds the host** (container id): a `docker restart` keeps it; a recreated container fails
  closed. It also binds the device string (`cuda`).
- **V4:** `d2`, `core` and `paper` refuse to start once any `outputs/stage2/full/held/**/*.npz` exists. A rerun
  forced by a failed V check goes through `ct2_run.py verdict --replace "<reason>"`, and the report lists it.
- **Never run `ct2_percept.py --smoke` or `ct_percept.py --smoke` by hand** in the main checkout. Use `ct2_smoke.py`
  with a new scratch folder.
- **JSON outputs are gitignored:** `stage2a.json`, `verdict_stage2.json`, `diag_stage2.json` need `git add -f`.
- **K-means** runs on one thread inside each Stage 1 run (by design, repeatable sums); the core and paper steps show
  long CPU-bound pauses between GPU bursts. That is expected, not a hang.
- `ct2_data.missing_ids` lists the `_s2` stores' IDs in sample mode too; it is a metadata audit, not a provider
  (re-review note).
- Unattended: delete nothing (your own scratchpad excepted); list items in `.scratch/pending_deletions.md`.
- The repo is shared with "r10 decide 15": commit only your own files, pull before you push.
