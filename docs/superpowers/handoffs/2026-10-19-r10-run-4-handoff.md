## 5. Code and pitfalls

- **Do not edit `ms_train.py`, `ms_rows.py` or `ms_score.py` during the run.** Their hashes are in every head's
  config and in stage 0's PASS: an edit makes `--require-pass` fail, and the sheet asserts one code version per row
  (F5). If a code fix is unavoidable, rerun stage 0 and every row, and say so at the top of the report.
- **Never rerun a row by hand into `R/outputs/`** with other settings (`--max-epochs`, `--device`, `--set`): after F7
  any config difference retrains and replaces the verified heads (re-review note 1). Hand runs go to a scratch
  `--outdir`; `--smoke` runs must sit under the `SMOKE` path in `ms_train.py` (it asserts).
- `SCORER_VERSION` hashes `ms_score.py` and `pav_score.py` only; `pc_score`, `apc_data` and `pc_data` are not in it
  (re-review note 2). Nobody edits them in this run.
- The sheet skips `outputs/stage0/` and `outputs/cache/` as rows; stage 0's arrays only feed the "stage 1 network"
  bar.
- GPU runs do not repeat bitwise (T5 CUDA against CPU differs by up to 0.15 in an early dev loss); the tie band comes
  from three seeds (spec §8).
- Genre is scored on its 4,053 labelled paintings. Held data: none is read; everything is the frozen train-side
  sample (fit 13,400, dev 1,489, evaluation 5,000).
- If a queue step fails: its log is `R/queue_stage<N>_<step>.log`. Fix only what is plumbing (paths, a lock wait);
  anything that changes the trainer or scorer falls under the first point. Report a failed row as a result.
- Delete nothing; list items in `.scratch/pending_deletions.md`.
