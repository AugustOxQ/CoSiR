## 5. Code and pitfalls

- The Bash tool runs zsh (or fish): put multi-step jobs in a bash script under `/tmp/claude-0/`; zsh does not
  word-split `$VAR` commands.
- `eg_pinfer.py` without `--smoke` writes the stage ii plan lock (VL4) on first write; it now refuses while a
  non-deferred candidate lacks a stage 3 block. Never run it on the real outputs before stage i's stage 3 is done.
- A gate or regression file that exists is never rerun: after a fix, move the old file to a dated folder under
  `outputs/aside/` first (the build's are in `outputs/aside/20261025_final_fix/`). Delete nothing.
- After any change to `eg_score3.py` or its static imports, existing stage iii score files are refused ("stale
  code_sha256; move … aside"); `eg_queue.md` lists what to move.
- `eg_score.py --replace` needs `--candidates`; after a rewritten held output, move the stale
  `part2/partitions/<scale>/<arm>/<aspect>__s<seed>__*` files aside before the recompute.
- pytest's temp folder is `/tmp/pytest-of-root`; never `rm -r` through the parity trees `/tmp/claude-0/eg06_parity_*`
  (they link into 12-24's frozen outputs). `rb_paths.OUTPUTS` reads `RB_OUTPUTS` at import: never set it.
- Run stage iii through its queue: the queue's preflight (`eg_score3.py check-code`) refuses stale score files, but a
  hand-run `all`, `fresh` or `report` reads earlier score files without that check (re-review, minor). By hand, run
  `check-code` first.
- P export sidecars carry `code_sha256`: `eg_pinfer.py` and the static closure of its imports in this round's and the
  RB folders, without `eg_run` (the driver). A forced VL3 rerun (`--forced-vl3`) needs the same weights and this hash,
  so any edit to `eg_pinfer`, `rb_student`, `rb_matched`, `rb_encoders`, `rb_data` and their closure refuses it; an
  unrelated commit does not. Older-round modules (`ms_train`, `ct_*`) are outside the hash (agent default).
- After an ArtELingo-28 store fix, `replace` does not touch a stage 5 block whose cause is that V5 failure: make the
  matched arm's ArtELingo-28 outputs (`eg_matched.py ... --kinds a28`), then `eg_score.py --stage 5 --candidates K
  --replace "<reason>"` by hand (`eg_queue.md`, "Replace a kept no-outcome block"; the first step is not checked).
- In the `gpu` chain, the `cpu_i` report queues overlap stage ii's `lift` and `vl2`: up to 16 one-thread workers.
- The stage iii `report` step took 514 s at smoke scale; 12-24's stage 3 reporter took 22.5 min for one candidate
  on a loaded machine.
