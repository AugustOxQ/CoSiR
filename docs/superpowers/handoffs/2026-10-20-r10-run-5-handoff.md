## 5. Code and pitfalls

- **Run from `/project/CoSiR`.** Outputs land in the main checkout's round folder (`outputs/`, gitignored); stage 0
  and stage 1 must run from the same checkout, since the pass records absolute paths.
- **Every code edit after stage 0** to a covered file (`ct_*.py`, `ct_queue*.sh`, `DECISION_RULE.md`, the six
  reference round folders) fails `require_pass` and forces a stage 0 rerun (seed 0 retraining). Stage 0 retraining
  is refused once any held NPZ exists.
- **The pass is tied to the host name** (the container id): a `docker restart` keeps it, a recreated container fails
  closed and needs a new stage 0.
- **Never run `ct_percept.py --smoke` by hand** in the main checkout: its smoke training writes the full-run paths
  (re-review note, not fixed in code). Use `ct_smoke.py` with a new scratch destination.
- **Verdict rerun** forced by a failed V check (V4): `ct_run.py verdict --replace "<reason>"`, and a report entry.
- **JSON outputs are gitignored** (`*.json`): `stage0.json`, `verdict_stage1.json`, `diag_stage1.json` need
  `git add -f` to be committed.
- Only `ct_run.py` and the queue scripts are the intended entry points; the module CLIs now refuse held work
  without a pass.
- `subagent-watch` prints "No running subagents" while worker subagents run; rely on completion notices.
- Unattended: delete nothing (smoke outputs in the session's own scratchpad excepted); list items in
  `.scratch/pending_deletions.md`.
